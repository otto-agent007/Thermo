# Research queue

The owner curates this file. The [research loop](research-loop.md) takes the
top `open` row that has no proposal yet, probes it, drafts a frozen protocol
and asks the owner on Discord before running anything. It never adds, edits
or reorders rows; a study's report PR only marks its own row `done`.

One row is one question, one target family and one metric. The `Row` id
becomes the branch `research/<row>` and the protocol
`docs/experiments/<row>.md`, so use lowercase letters, digits and hyphens.
Statuses: `open` (the loop may take it), `held` (skip for now), `done`,
`dropped`. Keep `|` out of the cells. A row the owner declined is skipped
until its text changes.

Standing rules for opening rows (drafted 2026-11-12 from the
[mechanism-rows debrief](research/2026-11-12-loop-debrief-mechanism-rows.md);
they take effect when the owner merges them):

- A row that waits on an owner answer or on another row's result is `held`,
  with the condition in its notes. `open` means the loop may spend a probe on
  it now.
- A row that owes a source card names it, and the card is due before the row
  closes, not only before a protocol.
- A row that compares against an earlier failure or baseline says which
  result must be reproduced first.
- A queue change that cites a new proposal note waits for CI and one second
  read of that note (the review lane or the director) before it merges.

Standing rules for task rows (owner, on direction review D-0003 in #120):

- Headline reads and writes per sample. Report the projected joule only as a
  band, from the sealed profile's write constant to clamp loads priced at the
  read constant, until Extropic publishes a clamp-only constant.
- Price the conventional baseline too: count its multiply-accumulates per
  sample and report them at 0.1, 1 and 10 pJ per MAC, labelled
  `calibrated_projection` with the constant stated, so both sides of a
  comparison are projected joules rather than joules against CPU seconds.
