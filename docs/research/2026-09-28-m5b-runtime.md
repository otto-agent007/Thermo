# M5b runtime calibration and recovery

September 28, 2026 UTC / September 27 owner discussion.

The M5b runner is implemented. The complete 80-reference/720-cell study has
**not run**. This bounded calibration measures the cost of exact calculations
and exercises recovery; it does not establish scientific trends over the
frozen cap/K/precision grid.

## What was measured

One M5a base chain: reading B, seed 0, variational compilation, cap 1.
The benchmark contains its authenticated source replay and adaptive large-K
check, one K=4 cell using original parameters, and one 8-bit precision cell
using exact marginalization. All three units are recomputed from persisted
evidence before completion. There is no refitting and zero generated samples.

The CPU session reports an 8-CPU quota and an 8-GiB cgroup memory limit.
Every worker uses one BLAS thread. Process RSS and session cgroup counters
are runtime observations, not physical-device performance evidence.

Final-code calibration measured the following one-worker unit costs:

| Unit | Generation seconds | Replay seconds | Preparation |
|---|---:|---:|---|
| Source reference and adaptive large-K check | 40.54 | 42.64 | Cold in both phases; about 15–16 seconds included |
| K=4 | 23.91 | 8.91 | Cold after the deliberate restart; warm in replay |
| 8-bit precision | 8.66 | 8.63 | Warm in both phases |

Three workers completed generation plus full replay in **82.82 seconds**.
Peak worker RSS was about **0.89 GiB**; the session memory high-water mark
reached **4.56 GiB**. OOM counters did not increase. The one-worker recovery
exercise took 134.80 seconds across its interrupted and resumed attempts,
including repeated context preparation after restart.

The bounded calibration observations and recovery sequence are summarized
here. Benchmark run directories are local diagnostics rather than committed
scientific evidence; the eventual full study has a separate archive and gate.

The three-worker benchmark's small grid contains one long reference unit,
so its total speedup is limited by that unit and duplicated context setup.
The production grid has ten units per base chain and can reuse each worker's
reference matrices. It must still account for rebuilding those references
in multiple workers.

## Planning estimate

Let `r` be source/reference seconds, `c` mean new-cell seconds excluding
preparation, and `p` mean cold-context preparation seconds. For `w` workers,
a planning model for generation **and** full replay is:

`2 * (80*r + 720*c + 80*(w-1)*p) / w`.

This accounts for the reference unit's included preparation and up to w-1
additional preparations per base. With r≈42, c≈8.5 and p≈15.5 seconds,
the central estimates are about 5.3 hours with one worker and 2.2 hours with
three. Allow roughly **5–6 hours with one worker or 2–3 hours with three**.
Use three on this session: it was measured and leaves memory headroom.

These estimates apply to this 12-spin exact evaluator and include persisted
replay. Other seeds/caps, host load, checkpoint overhead and numerical
conditioning can change them. A numerical-integrity failure stops safely
with a saved checkpoint; an amended method would need review. The K power
is evaluated analytically, so wall time does not grow linearly with K even
though the hypothetical Gibbs work count does.

## Recovery and commands

```bash
uv run python -m thermo_lab.meta_ebm_thermalization \
  --output-dir results/m5b-benchmark --benchmark --workers 1
uv run python -m thermo_lab.meta_ebm_thermalization \
  --output-dir results/m5b-benchmark --benchmark --workers 1 --resume
uv run python -m thermo_lab.meta_ebm_thermalization \
  --output-dir results/m5b-benchmark-three-workers --benchmark --workers 3
```

The recovery exercise sent SIGTERM to the Python runner after its first
reference was saved. It exited 130, retained the result and a diagnostic
exit/status record, and left no completion marker. Resume reused that
reference without reevaluating its generation, completed both remaining
cells, then replayed all three units. The retained reference was exactly
unchanged as a JSON value. A completed resume verifies bound evidence
without regenerating it.

The runner persists `execution-checkpoint.json.gz`, `run-status.json`,
flushed `run.log` and `exit.json`. Checkpoints include individual replay
receipts as well as generated units, so replay interruptions do not force
repeated generation or restart already completed replay. Request, source,
archive and Python/NumPy/SciPy mismatches are rejected.

Full-study commands and exact completion requirements are in the
[release gate](../release-gates.md#m5b-inner-thermalization-and-precision-sensitivity).
The benchmark completion marker is explicitly `m5b_benchmark_complete`;
it cannot certify the full study.

## Verification

The focused tests cover independent joint hidden/output enumeration,
compatible visible-joint invariance, tiny positive escape rates, rounding
boundaries, original source parameters, the complete grid, generated and
replayed checkpoints, changed requests/runtimes, occupied output locks and
altered evidence. The full production grid remains a local gate, and its
archive replay tests are enabled when the full archive is present.

Independent implementation review found an archive-replacement race during
replay. A failing regression reproduced it; publication now authenticates
one byte snapshot, detects replacement and binds completion to those same
validated bytes. The final benchmarks above were rerun after that fix.
Repository-wide Ruff checks pass. Broader suite results are reported in
the implementation PR.
